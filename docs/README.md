# Mirexis Documentation

The documentation is organised by responsibility so that design ambition, current
implementation, active planning, and generated evidence do not contradict one another.

## Active documents

- [`../README.md`](../README.md) — concise project status, controls, and developer entry.
- [`../MIREXIS.md`](../MIREXIS.md) — creative vision for the finished game; some content
  is intentionally aspirational.
- [`../TECHNICAL_DESIGN.md`](../TECHNICAL_DESIGN.md) — implemented architecture and
  technical contracts.
- [`PLAYABLE_GAME_PHASE_1.md`](PLAYABLE_GAME_PHASE_1.md) — current production roadmap.
- [`UI_GRAPHICS_VISUAL_SPEC.md`](UI_GRAPHICS_VISUAL_SPEC.md) — visual language and UI
  principles.

## Supporting material

- `research/` contains source research used to establish the visual direction.
- `verification/` contains generated capture references and the manifest used by tests.
  These files record regression evidence; they are not statements of product readiness.

Project-wide Rust and Macroquad rules remain in `../AGENTS.md`, `../CODE_STANDARDS.md`,
and `../MACROQUAD_TOOLKIT.md`.
